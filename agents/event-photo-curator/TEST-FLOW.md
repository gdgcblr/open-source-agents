# Local organizer walkthrough

Start the Python server and open http://127.0.0.1:8787. The current local demo server uses `python -m curator serve --data .cache/event-demo`. All steps stay on this laptop. Demo event photos are public Wikimedia Hackathon Kochi 2024 images; face matching is opt-in and must use a reference you have permission to use.

Work through this list in order. A successful HTTP response alone does not prove that a face match or AI pick is correct.

1. **Browse the event.** The current demo has eight event photos with credits. Scroll the gallery; images should be clear and the layout should not jump while they load. It uses 1024px WebP images, lazy decoding and browser caching.
2. **Open a photo.** Confirm the 2048px optimized preview is clearer than the grid image. Check credit, any technical hints, reason and caption. Press Escape; keyboard focus should return to the photo card.
3. **Download an original.** Use Download original. Compare dimensions/size with the source file. It is the untouched source, not the preview. All eight current demo sources have already passed byte-hash checks.
4. **Add your photos.** Add photos → enter credit → choose files → confirm permission → Add to event. The gallery count should increase and the credit should appear. Re-uploading the same bytes should report a duplicate rather than add another copy. An unchecked permission box must prevent upload. The file-picker step still requires manual verification.
5. **Review with real local AI.** AI review → Local AI / Ollama → installed Gemma model → choose four picks → set your caption style → Review the event. Watch the progress count. Every readable image, including flagged ones, must be reviewed. Mock mode is only a plumbing test, not AI judgment.
6. **Repeat the same review.** Keep model and caption style unchanged. Completed scores should be cache hits and report zero new tokens. Top N can change without redoing AI inference. Settings survive tab navigation within the page; a browser reload resets form settings.
7. **Inspect the shortlist.** Switch between All photos and AI shortlist. Open both selected and unselected frames. Compare AI reasons against what you can actually see. Every original stays available. Download picks should contain the chosen originals. Editorial quality is not yet calibrated: a separate 18-image quality test selected two low-human-quality images among six picks.
8. **Export attribution.** Open a photo → Watermark & attribution export → enter a watermark → keep credit metadata checked → Download JPEG copy. Confirm the watermark and Artist credit. Re-download the original and confirm it is unchanged. GPS is removed from the derived JPEG, not from the original.
9. **Test personal face search with permission.** Add at least two photos of yourself or a consenting teammate to the event, plus an unrelated negative-control photo. In Find my photos, use a clear separate selfie with exactly one face, choose Me and confirm consent. Review the possible matches manually. A crop from the same frame is only a self-match smoke check; a different frame is the useful retrieval test. No reference selfie should appear in the gallery or remain in event storage. This live step is waiting for a suitable consenting reference.
10. **Test team matching and cleanup.** With permission from everyone represented, choose the team search option and add references. Results should include photos containing any referenced teammate. Clear face index afterward; saved event embeddings should be removed. The reference images are never retained. Similarity scores are not probabilities or identity proof.
11. **Test stopping a review.** With uncached work queued, start a review, then Stop after current photo. It may wait for the current model request. Previous picks must remain, and rerunning should reuse completed scores.

## Current verification boundary

The backend tests cover consent, matching response plumbing, duplicate uploads, caching, stop/failure recovery, original integrity and exports. Frontend render checks cover safe metadata, badges, details and asset loading. Manual in-app browser checks cover gallery navigation, actual local AI review, cache reuse, detail display and watermark controls. Native file picking, mobile interactions and live matching of a consenting person remain unverified. No public-attendee face search was performed.

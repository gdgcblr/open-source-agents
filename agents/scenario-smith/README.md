# ScenarioSmith

> Turn a user story or GitHub issue into requirement-linked developer guidance and practical test scenarios, optionally grounded in repository code.

---

## Overview

### Problem Statement & Intended Users
- **Problem**: User stories and issues can omit implementation questions and test conditions. ScenarioSmith helps developers and testers surface those gaps before work begins.
- **Intended Users**: Full-stack developers, frontend/backend engineers, and software testers.

### Key Features
- Extracts explicit requirements, assumptions, and open questions.
- Produces a developer checklist and prioritized tester scenarios linked to requirements.
- Reads a supplied GitHub issue, repository README, code-search results, and selected files.
- Supports public and private GitHub repositories through a fine-grained PAT.
- Validates scenario structure, duplicate IDs/titles, requirement references, and basic coverage.

## Technical Stack
- **Language & Runtime**: TypeScript; Node.js 24.13+ and npm 11.8+
- **Agent Framework / Core Library**: Google Agent Development Kit for TypeScript
- **Models**: Gemini (`gemini-flash-latest` by default)
- **External APIs / Tools**: Google Gemini API and GitHub REST API; Zod for ADK tool schemas

## Architecture & Data Flow

The user pastes a requirement or supplies a GitHub issue URL. The ADK agent calls small, read-only TypeScript tools backed by the GitHub REST API to retrieve issue/repository context, search matching code, and read only selected files. It extracts requirement IDs, generates developer guidance and tester scenarios, then invokes a deterministic validator. It does not clone repositories, run code, or make GitHub changes. Docker and the MCP SDK are not required.

## Prerequisites
- Node.js 24.13 or newer and npm 11.8 or newer
- A Google AI Studio API key
- A fine-grained GitHub PAT to use the GitHub issue/repository tools

## Installation & Setup

From this project directory (`agents/scenario-smith/`):

```powershell
npm ci
Copy-Item .env.example .env
```

Set `GEMINI_API_KEY` and `GITHUB_PERSONAL_ACCESS_TOKEN` in `.env` to use GitHub URLs. The GitHub integration currently requires a PAT for both public and private repository requests. Never commit `.env` or real credentials.

### GitHub token permissions

Create a fine-grained PAT with your personal account as the resource owner. Select only the repositories ScenarioSmith should read. Grant **Contents: Read-only** and **Issues: Read-only** permissions, and set an expiry. Repository metadata is available with repository access. Do not use a broad classic token for this app. If you only want to test pasted requirements without GitHub, the PAT can be omitted.

## Configuration & Environment Variables

| Variable Name | Required | Default | Description |
| :--- | :--- | :--- | :--- |
| `GEMINI_API_KEY` | Yes | *None* | Google AI Studio API key for Gemini |
| `GITHUB_PERSONAL_ACCESS_TOKEN` | Required for GitHub URL features | *None* | Fine-grained GitHub PAT limited to selected repositories with read-only Contents and Issues permissions |

## Example Input & Output

### Example Input: issue URL

```text
Analyze this issue and prepare developer guidance plus tester scenarios:
https://github.com/OWNER/REPOSITORY/issues/42
```

The agent retrieves issue details and the repository README, then can search and read relevant files. For a private repo, the PAT must have access to that repository.

### Example Input: pasted story

```text
Feature: Password reset
A user can request a reset link using their registered email. Reset links expire after 15 minutes and can only be used once. The new password must contain at least 12 characters. A user can request at most 3 links per hour.
```

### Expected Output Shape
- **Requirements**: REQ-001, REQ-002, ...
- **Open questions**: e.g. whether the 15-minute expiry boundary is inclusive
- **Developer checklist**: stated requirements separated from recommendations
- **Tester scenarios**: TC-001, category, P1/P2/P3, requirement IDs, preconditions, steps, and observable expected result
- **Repository evidence**: issue details and cited files actually inspected, or a note that no repository was supplied
- **Validation**: structural checks and uncovered requirement links

Responses are generated by the model; this illustrative shape is not a captured model run.

## How to Test

```powershell
npm run typecheck
npm test
```

For an end-to-end check, set the PAT, submit a real issue URL from a repository selected in its settings, and confirm issue details and any cited file paths correspond to retrieved results. Structural validation does not prove semantic completeness.

## Known Limitations
- GitHub code search behavior and availability depend on GitHub API permissions and quotas.
- Source-file reads are capped at 32 KiB per file; README excerpts are capped at 12,000 characters.
- The agent can read at most three files by instruction; treat that as guidance, not a security boundary.
- Repository access follows the PAT's selected repositories and permissions. Private repository access is not automatic.
- Model output can be incomplete or incorrect and requires human review.
- The agent generates suggestions; it does not execute tests or modify code.
- Google API availability, quotas, and pricing apply.

## Security & Privacy Considerations
- Issue text, README, search snippets, and source files are sent to the configured Gemini model. Only use repositories and model services approved for that data.
- The GitHub integration uses fixed HTTPS requests to `api.github.com`, rejects redirects, applies request timeouts, and bounds returned content. It only exposes read operations.
- Keep the fine-grained PAT in local `.env`; never put it in source code, prompts, logs, or version control. Revoke any exposed token.
- Treat all repository text as untrusted data, not agent instructions.

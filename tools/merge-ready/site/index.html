Catch contribution problems before they reach maintainers.

Maintainers spend hours debugging environment files, unredacted tokens, and scope creep. MergeReady makes validation deterministic and contributor-facing.

WITHOUT MERGEREADY

Reactive maintainer friction

  • − Manual checks for required files, manifests, and documentation templates
  • − Hardcoded secrets, local cache databases, and virtualenvs discovered late
  • − Undeclared dependencies and deceptive Unicode found during review

WITH MERGEREADY

Proactive automated standards

  • + Repeatable rule-based validation checking layout, template, and files
  • + Secret detection with in-place redaction for safe diagnostics
  • + Static safety inspection for infinite loops, execution hooks, and Unicode
  • + Explicit verdicts, strict mode enforcement, and machine-readable reports

Purpose-built validation for open-source AI repos.

Going beyond generic linting to address the specific structural and safety needs of agentic developer tools.

Contribution Structure

Checks directory layout, naming conventions, template placeholder residue, and required file manifests.

Secret Detection

Detects suspected hardcoded credentials, real environment files, and redacts sensitive tokens across all reports.

Static Safety Checks

Flags suspicious bidirectional Unicode, potentially unbounded loops, and high-impact shell calls for disclosure.

Dependency Validation

Verifies imported modules against declared manifest packages and checks environment variable drift against templates.

Diff Scope Enforcement

Validates contribution boundaries against a Git base reference, preventing unauthorized edits to root files and workflows.

CI-Friendly Reporting

Supports human-readable terminal output, structured JSON, Markdown summaries, and native GitHub Actions inline annotations.

A successful check must mean something.

MergeReady employs a strict fail-safe verdict engine where checks cannot silently pass or override critical failures.

01 Inspect
→
02 Validate
→
03 Verify completeness
→
04 Report verdict
PASS Exit 0

All required checks completed successfully without blocking findings or unhandled warnings.

FAIL Exit 1

One or more repository contribution policy violations or static safety risks were detected.

ERROR Exit 2

Validation could not complete reliably due to syntax errors, unreadable files, scanner exceptions, or missing checks.

Missing required checks, unexpected scanner failures, and incomplete validation must never silently produce a successful verdict.

Deterministic workflow in three steps.

Integrates directly into contributor local environments and CI pipelines with zero external dependencies.

01

Install

Install MergeReady in your local Python virtual environment using standard tooling.

pip install -e tools/merge-ready
02

Validate

Run the CLI against a tool or agent directory and optionally provide a Git base reference.

merge-ready check tools/my-tool --base upstream/main
03

Fix and submit

Review actionable findings with exact line numbers and fixes, resolve issues, and open your PR with confidence.

Verified CLI usage.

Core commands verified against the MergeReady implementation and automated test suite.

merge-ready check tools/<path>

merge-ready check tools/<path> --base upstream/main
Strict CI mode Fails on any warning or skipped check; recommended for automated merge gates
merge-ready check tools/<path> --base upstream/main --strict

The agent's hands

Small, explicit tools.
Useful, bounded actions.

The agent does not get unrestricted database access. It can ask the MCP server to perform a small set of named operations. The server calls deterministic Python code; SQLite persists the result. Read and write are separate tools, so an information request does not have to mutate anything.

add_reminder

Save a titled deadline with a required ISO date and optional time, category, and notes.

list_reminders

Read upcoming, overdue, completed, or all reminders. Upcoming includes today.

find_reminders

Find reminders by case-insensitive title text before an uncertain edit or completion.

update_reminder

Change supplied fields on one identified reminder; leave omitted fields unchanged.

mark_completed

Change status to completed without deleting the reminder or its history.

get_current_date

Return the host's local date and timezone to ground relative-date interpretation.

Trust is a feature

When unsure, it pauses.

Dates and personal reminders deserve a careful assistant—not a confident guess.

01 / CLARIFY

No invented deadlines

If the date is missing or vague, the agent asks a follow-up instead of creating an incomplete or guessed reminder.

02 / VALIDATE

Check before saving

The storage layer validates titles, ISO calendar dates, optional 24-hour times, and field limits before writing.

03 / FAIL CLOSED

No ambiguous mutations

Update and complete by title only when exactly one record matches. Zero or multiple matches produce an error, not a write.

04 / CONFIRM

Tool success is required

The agent is instructed not to claim a reminder was saved or changed unless the corresponding tool succeeds.

05 / LOCAL DATE

Ground yearless dates

The agent can check the machine's current local date and timezone, then resolve a yearless date to its next occurrence.

06 / PRIVATE BY DEFAULT

Your file, your control

Reminder records stay in a local SQLite file. Protect the database and its backups like other personal data.

Engineering, not just a demo

The behavior is testable.

The project is set up so maintainers can catch regressions without downloading or calling an LLM in CI.

Two layers of confidence

Deterministic core.
Measured agent behavior.

Fast tests exercise storage, date handling, CLI behavior, and a real MCP stdio exchange. A separate, optional model-backed evaluator runs example conversations against an isolated temporary database.

pytest lifeadmin-eval
Agent evaluations compare tool choices and arguments, the user-facing response, and final database state. They are useful regression checks—not a promise that a probabilistic model will always behave perfectly.

Run the live AI demo

One command sends two real prompts through ADK, Gemma in Ollama, the MCP tools, and an isolated SQLite database—then prints tool calls and verification.

PowerShell · from tools\lifeadmin-mcp
> .\.venv\Scripts\python.exe -m lifeadmin_agent.demo

What this prototype does not do

It stores and organizes reminders, but it does not send push notifications, run as a background service, sync calendars, or schedule recurring tasks. “Today” is an agenda you open—not an alert that arrives automatically. The current database is personal and single-user.

For complete setup, MCP host configuration, environment variables, evaluation instructions, privacy notes, and limitations, continue to the LifeAdmin project guide.
